## 1. 概述

HmChat 目前是纯 ArkTS / ArkUI 的原生 Telegram 客户端，全部外联流量只经 TDLib 一条出口（`docs/integration/harlgram-baseline.md` §3.5）。本特性把 FlClashX-OHOS 已验证可运行的 mihomo（Go）代理内核能力融合进 HmChat，使用户可以在 HmChat 内直接获得设备级代理能力，而**不引入 Flutter UI 或 Flutter 运行时**。

融合形态采用「形态 A：单一 HmChat 应用内集成」：

- UI 与业务继续使用 HmChat 现有 ArkUI 页面、HDS 组件与 `pages/Index.ets` 导航结构。
- 代理内核只运行在新增的 VPN 扩展进程中，主 Telegram 进程不加载内核。
- UI 进程与扩展进程通过受鉴权的本机回环 RPC 通信，不使用固定端口、不允许无鉴权连接。
- 首个可交付 MVP 是「设置 → 网络代理」二级页，覆盖 VPN 开关、订阅 URL 导入、本地 Clash YAML 导入、节点列表与选择、延迟测速、当前状态与错误提示。

本规格的判定标准是「用户可观察的行为 + 可复查的证据」，不以「代码已写」「组件已用」「内核能启动」代替真实可用。

## 2. 目标

- **G1** 用户可在 HmChat 设置中打开「网络代理」二级页，完成订阅导入、节点选择、启停代理的完整闭环，无需安装第二个应用。
- **G2** 代理生效范围为设备级（系统只有一个 VPN 通道），默认全局代理所有应用；额外提供一个「仅 HmChat 走代理」开关。
- **G3** 任一失败路径（内核缺失、授权被拒、TUN 未建立、配置无效、RPC 不可达、protect 失败）都必须给出明确、可操作、非静默的状态与错误，**禁止伪造 Ready / 已连接**。
- **G4** 代理能力不破坏现有 TDLib 登录、消息、媒体、草稿、账户切换与媒体自动下载策略。
- **G5** 订阅 URL、节点密码 / UUID 等敏感数据进入 HarmonyOS Asset 或受保护文件，不进入 Preferences 明文、日志、截图与公开 artifacts。
- **G6** 交付物在真实 SDK 26 下编译通过，遵守 `scripts/ci/verify-hap.py` 与许可证门禁；GPL 对应源码未补齐前不发布含内核的 HAP。
- **G7** 手机单栏、未展开形态优先完成真实功能与 UI/UX；其他形态如实标注未验证。

## 3. 非目标（明确不做）

以下能力**不属于**本规格范围，不得在实现中以「顺手做了」的方式引入，也不得在 README / 页面文案中暗示已支持：

1. 规则编辑器、规则集可视化编辑、脚本覆写（override / script）编辑界面。
2. 完整分应用代理列表（逐应用勾选 accept / reject 名单）。
3. TUN 栈切换（gVisor / system 栈切换开关）。
4. 配置备份与恢复、配置导入导出文件包。
5. 桌面快捷磁贴、系统小组件、TV 形态、系统全局代理设置写入。
6. 引入 Flutter UI、Flutter 运行时、Flutter 插件 HAR 或 WebView 包装页面。
7. 修改现有 bundleName 计划、签名配置、ACL 或证书。
8. `x86_64` 或其他 ABI 的内核产物；本轮仍为 `arm64-v8a`。
9. 展开形态、多窗口、分屏、平板的专项适配验收（设计目标保留，验收留待后续并有真机时执行）。
10. 订阅的云端托管、账号同步、跨设备同步。
11. 以本规格替代 Telegram API 服务条款、AppGallery 上架资质与隐私政策合规审查。

## 4. 术语

| 术语 | 定义 |
| --- | --- |
| 内核 / core | mihomo（Go，c-shared 构建）代理内核，以独立 `.so` 形式随应用分发，仅运行在 VPN 扩展进程。 |
| 桥 / bridge | NAPI 层，把 ArkTS 调用转成内核 C ABI 调用，并负责事件回投与 protect 握手。**仅存在于扩展进程**。 |
| VPN 扩展 | `VpnExtensionAbility`（`type: "vpn"`）进程，持有 TUN fd、内核与 RPC 服务端。 |
| UI 进程 | HmChat 主进程（`EntryAbility`），承载 ArkUI 页面与 TDLib。不加载内核。 |
| protect | TUN 场景下把「代理自身出站 socket」从本机 TUN 路由中排除的动作；不做或失败会形成流量环路。 |
| 配置 / profile | 一份可被内核加载的代理配置，来源为订阅 URL 或本地 Clash YAML 文件。 |
| 节点 / node | 配置中的单个出站代理项；节点凭据（密码 / UUID / 私钥）属敏感数据。 |
| 代理组 / group | 配置中节点集合的分组（如手动选择组、自动测速组），本规格只读呈现，不提供规则编辑。 |
| 订阅 | 一个可远程更新的配置来源 URL；URL 本身常含 token，等同凭据。 |
| 延迟测速 | 对节点发起连通性/时延探测，结果用于排序与选择参考，**不等于**连接已可用。 |
| 状态机 | 代理运行状态的唯一真值来源，见 §6。 |
| HDS | HarmonyOS Design 官方组件与样式（`HdsNavigation`、`HdsNavDestination`、`HdsListItemCard` 等）。 |
| 待确认 | 必须读到 FlClashX `core/` / `lib/` 源码、固定 TDLib schema 或真机验证后才能定论的事实。 |

## 5. 约束与前提

### 5.1 证据分级

本规格沿用项目基线文档的分级：

- **【事实】** 直接读到的代码、配置或本机 SDK 声明，可作为需求依据。
- **【推断】** 由事实组合出的工程判断，尚未编译或设备验证；对应需求必须以「行为可验证」方式表述，不锁定实现。
- **【待确认】** 依赖缺失的 `core/`、`lib/`、固定 TDLib schema、真机或商店政策；在 §9 集中列出，任何实现不得据猜测补齐字段名。

### 5.2 硬约束（必须同时满足）

| 编号 | 约束 | 依据 |
| --- | --- | --- |
| C1 | 禁止伪造 Ready：内核未加载、VPN 未授权、TUN 未建立、无有效配置时，不得呈现「已连接」或任何等价成功语义。 | `AGENTS.md`「缺少 `.so`…禁止伪造 Ready」；`harlgram-baseline.md` §7.5 |
| C2 | 主 Telegram 进程不得加载 `libclash_core.so`；内核只住在 VPN 扩展进程。 | `flclash-baseline.md` §9.6；`harlgram-baseline.md` §7.2 |
| C3 | RPC 不得沿用固定端口 47471 且不得无鉴权；必须有会话 token、随机端口或等价防护。 | `flclash-baseline.md` §9.1、§9.9 |
| C4 | protect 必须可靠：队列容量、超时、失败可见，避免代理自身流量被自身 TUN 捕获形成环路。 | `flclash-baseline.md` §5.5、§9.3 |
| C5 | 订阅 URL、节点密码 / UUID 属敏感数据，必须进 Asset 或受保护文件，不得进 Preferences 明文、日志、截图、公开 artifacts。 | `harlgram-baseline.md` §4.2；`AGENTS.md`「真实账号与数据」 |
| C6 | 不破坏现有 TDLib 登录、消息、媒体、草稿；`MediaNetworkMonitor` 不能把自有 VPN 误判为漫游。 | `harlgram-baseline.md` §7.6 |
| C7 | 构建必须通过真实 SDK 26 编译；遵守 `verify-hap.py` 与许可证门禁；GPL 对应源码未补齐前不得发布含内核的 HAP。 | `docs/LICENSING.md` §「将来分发 HAP 时」；`flclash-baseline.md` §10.4 |
| C8 | 手机单栏、未展开形态优先；UI 遵循 HDS 与现有设置二级页模式。 | `docs/UI_GUIDELINES.md` §「必须遵守的 HDS 组件与交互基线」 |
| C9 | VPN 扩展内不得 import 被 SDK 禁用的 `contacts` / `geo` / `audio` / `camera` / `call` / `sim` / `sms` 模块。 | `harlgram-baseline.md` §5.2（SDK `@ohos.net.vpnExtension.d.ts` 警告） |
| C10 | 默认沿用 `bundleName xyz.3333189.harlgram`，不修改签名与构建配置；如后续调整由用户自行配置。 | 用户决策；`AGENTS.md`「脚本、设备与签名」 |
| C11 | 当前 `source-refs` 副本缺 `core/`、`lib/`、`pubspec.yaml`，只有 `ohos/`、预编译 `.so` 与头文件；依赖 core schema 的部分标为待确认，不得臆造 Action 字段。 | `flclash-baseline.md` §2.1、§8.4 |

### 5.3 前提假设

- **A1** 设备具备系统 VPN 授权能力，首次建立 TUN 时由系统弹出授权对话框（【待确认】拒绝后的系统行为与可重试性）。
- **A2** 用户拥有可用的代理订阅或本地 Clash YAML 配置；规格不对订阅服务商可用性作保证。
- **A3** 验收设备为已连接且用户指定的真机；真机不可用时使用已授权的手机模拟器，两者结果分开记录，模拟器结果不替代真机。
- **A4** 现有 TDLib、签名、账号与消息数据在开发过程中保持不受损；禁止在同 bundle 上做 ohosTest 安装/卸载循环。

## 6. 状态机

### 6.1 状态定义

| 状态 | 标识 | 用户可见主文案 | 允许的用户动作 |
| --- | --- | --- | --- |
| 未配置 | `unconfigured` | 「尚未导入配置」+ 次级说明「导入订阅或本地配置后即可开启」 | 导入订阅、导入 YAML |
| 未授权 | `unauthorized` | 「未获得 VPN 授权」+ 说明「系统未允许 HmChat 建立 VPN 连接」 | 重试授权、关闭 |
| 准备中 | `preparing` | 「正在启动代理…」 | 取消、查看错误详情 |
| 已连接 | `connected` | 「已连接」+ 当前节点名（来自内核实际生效值） | 关闭、切换节点 |
| 已停止 | `stopped` | 「已停止」 | 开启、管理配置 |
| 失败 | `failed` | 「启动失败」+ 具体原因与下一步建议 | 重试、查看错误详情、导入/修正配置 |

补充约束：

- 「配置已导入但从未开启」属于 `stopped`，不是 `unconfigured`；`unconfigured` 只表示**没有任何可用配置**。
- 「内核进程已起但 TUN 未建立」「TUN 已建立但内核未加载」都不是 `connected`，分别归入 `preparing` 或 `failed`。
- 状态文案不得出现开发者术语（路径、SDK、ABI、Action 名称）；技术细节只进开发者入口或文档。

### 6.2 状态迁移

| 起始状态 | 触发 | 目标状态 | 说明 |
| --- | --- | --- | --- |
| `unconfigured` | 成功导入并保存有效配置 | `stopped` | 导入不等于启动，不得直接进入 `connected` |
| `unconfigured` | 用户开启开关但无有效配置 | `unconfigured` | 开关回到关闭位，给出「请先导入配置」提示 |
| `stopped` | 用户开启且配置有效 | `preparing` | 启动扩展、加载内核、请求 TUN |
| `stopped` | 配置被删除至无有效配置 | `unconfigured` | 顺带清理运行时引用 |
| `preparing` | 内核加载成功 + TUN fd 有效 + 路由配置生效 | `connected` | 见 §7.2 REQ-PROXY-017 的三重证据 |
| `preparing` | 首次授权被用户拒绝 | `unauthorized` | 记录可恢复原因，不重复弹窗 |
| `preparing` | 内核加载失败 / 内核缺失 / TUN 建立失败 / 启动超时 | `failed` | 必须携带具体错误码与建议 |
| `preparing` | 用户在准备中取消 | `stopped` | 必须等待资源释放完成再落状态 |
| `connected` | 用户关闭 | `stopped` | 经内部停止阶段，停止完成后才落 `stopped` |
| `connected` | 系统撤销 VPN / 扩展进程被回收 / 连接断开 | `unauthorized` 或 `failed` | 依原因区分；不得停留在 `connected` |
| `unauthorized` | 用户重试并授予授权 | `preparing` | — |
| `failed` | 用户重试 | `preparing` | 自动重试需有次数与退避上限（REQ-PROXY-068） |
| 任意状态 | 应用重启 / 进程被系统回收 | `stopped` 或 `unconfigured` | 由配置存在性决定；**禁止**恢复为 `connected` |
| 任意状态 | 所选配置在外部被删除/失效 | 依配置存在性 → `unconfigured` | 先停止再落状态 |

### 6.3 状态不变量

- **I1** 只有 `connected` 可以显示「已连接」及任何绿色/成功视觉；`preparing` 必须有可见的进行中语义。
- **I2** 状态以扩展进程回传的事实为准，UI 不得根据「开关已点」「配置已导入」「内核版本已读到」自行推断 `connected`。
- **I3** 每个状态在应用重启后必须能由持久化配置 + 运行时探测重建，不允许依赖易失内存。
- **I4** 任何 `failed` 必须至少包含：可读原因、可执行下一步；不允许长期停留「未知错误」。
- **I5** 代理状态与 `telegram.ready` / 连接状态完全独立，互不复用、互不覆盖（REQ-PROXY-071）。

## 7. 需求条目

需求编号规则：`REQ-PROXY-<三位序号>`。每条需求包含触发条件（EARS 句式）、系统行为与可验证的验收标准。凡标注 **【待确认】** 的条目，其具体协议/字段/平台行为必须在 §9 清单关闭后才可判定为完成。

### 7.1 设置入口与代理页面

#### REQ-PROXY-001 设置页提供「网络代理」入口

**EARS**：当用户位于设置页时，系统应提供「网络代理」设置行，点击后进入网络代理二级页。

**验收标准**
- **Given** 设置页可见，**When** 用户浏览「数据与存储」分组，**Then** 可见「网络代理」行，使用 HDS 设置行样式（标题 + 右侧摘要 + 跳转指示）。
- **Given** 用户点击该行，**Then** 进入网络代理页；返回后回到设置页原位置。
- [ ] 入口不在聊天详情或会话列表重复出现（进入代理页不得因此中断当前聊天）。

#### REQ-PROXY-002 入口摘要反映真实状态

**EARS**：当代理状态变化时，系统应更新设置页「网络代理」行摘要，使其与当前状态一致。

**验收标准**
- **Given** 状态为 `unconfigured`，**Then** 摘要为「未配置」。
- **Given** 状态为 `connected`，**Then** 摘要至少包含「已连接」；可选补充当前节点名。
- **Given** 状态为 `preparing` / `unauthorized` / `failed`，**Then** 摘要分别为「启动中」「未授权」「失败」，不得显示「已连接」。
- [ ] 摘要更新不依赖重新进入页面（返回设置页即刷新）。

#### REQ-PROXY-003 代理页为 HDS 二级页且返回语义正确

**EARS**：当用户打开网络代理页时，系统应使用 HDS 二级页容器呈现，并在系统返回与页面返回时回到设置页。

**验收标准**
- **Given** 代理页已打开，**Then** 顶部为 MINI 标题栏，标题「网络代理」，返回图标使用语义色（深色下不为黑色）。
- **Given** 用户点击返回或使用系统返回手势，**Then** 回到设置页（`currentTab = 2`），不落到会话列表。
- [ ] 代理页不新增底部 Tab，不改变现有三 Tab 结构与浮动底栏材质。
- [ ] 返回不重置账号、会话、草稿或列表滚动锚点。

#### REQ-PROXY-004 页面信息结构完整

**EARS**：网络代理页应至少包含状态区、主开关区、代理范围区、配置管理区（订阅与本地 YAML）、节点区四个逻辑区块。

**验收标准**
- **Given** 已有配置，**When** 用户进入页面，**Then** 从上到下可见：当前状态卡、VPN 开关、代理范围、配置列表、节点列表。
- **Given** 无配置，**Then** 配置区展示导入入口，节点区展示空态，开关不可用并说明原因。
- [ ] 区块之间使用现有设置页的分组标题与间距规范，不引入自定义卡片风格。

#### REQ-PROXY-005 未配置空态可操作

**EARS**：当系统处于 `unconfigured` 时，代理页应展示明确空态并提供两种导入入口。

**验收标准**
- **Given** 无任何配置，**Then** 显示「尚未导入配置」，并提供「导入订阅」与「导入本地配置」两个动作。
- **Given** 用户在主开关上尝试开启，**Then** 开关不进入开启态，并提示「请先导入配置」。
- [ ] 空态不含宣传文案、开发说明或实现进度描述。

#### REQ-PROXY-006 状态卡展示可核查事实

**EARS**：代理页应展示当前状态、生效节点、内核版本与最近错误四项事实。

**验收标准**
- **Given** `connected`，**Then** 状态卡显示「已连接」、内核实际生效的节点名、内核版本（来自扩展进程回传）。
- **Given** `failed`，**Then** 状态卡显示失败原因摘要，并可展开查看详情与建议。
- **Given** 内核版本不可得，**Then** 显示「未知」，不得编造版本号。
- [ ] 状态卡不显示订阅 URL、节点密码、UUID 或本机绝对路径。

#### REQ-PROXY-007 启停交互防重复与防抖

**EARS**：当代理处于 `preparing` 或正在停止时，系统应禁用主开关并阻止重复启停请求。

**验收标准**
- **Given** 用户已点击开启且状态为 `preparing`，**When** 再次点击，**Then** 不发起第二次启动请求，开关保持「进行中」语义。
- **Given** 用户快速连续点击开关，**Then** 系统按最后一次明确意图收敛，且最多只有一个进行中的启停操作。
- [ ] 启停进行中提供可见的进度或忙碌提示，不使用无反馈的假开关。

#### REQ-PROXY-008 页面按可用 vp 响应式布局

**EARS**：当窗口可用宽度变化时，系统应仅改变布局，不重置代理状态、配置、节点选择或滚动位置。

**验收标准**
- **Given** 宽度 `< 600 vp`，**Then** 单栏纵向布局，所有行与开关可点击，末项可滚动到浮动底栏之上。
- **Given** 宽度 `>= 600 vp`，**Then** 内容区保持可读最大宽度（居中或限制宽度），文字不拉满整屏。
- **Given** 跨越 599/600 vp 或 839/840 vp 边界，**Then** 状态、配置、节点选择与滚动位置保持不变。
- [ ] 长节点名、长订阅名、长错误文案在大字号下不裁切、不重叠。

#### REQ-PROXY-009 深浅色与根背景一致

**EARS**：当深浅色或页面切换时，系统应让代理页根背景与页面背景一致，并延伸到底部安全区。

**验收标准**
- **Given** 浅色 / 深色 / 跟随系统三种外观，**Then** 代理页正文、标题栏、分隔线、状态色对比度符合既有设置页标准。
- **Given** 底部手势区，**Then** 根背景与页面一致，无渐变遮罩色差。
- [ ] 切换外观不改变代理运行状态与所选开关值。

#### REQ-PROXY-010 文案简洁、可访问

**EARS**：代理页文案应面向用户动作与结果，并为交互控件提供无障碍描述。

**验收标准**
- **Given** 正常状态，**Then** 无宣传口号、无「ArkUI + C++」「Go 内核」等实现说明。
- **Given** 开关、测速按钮、删除按钮，**Then** 具备表达动作与结果的无障碍描述。
- [ ] 错误文案优先说明「下一步怎么做」，技术细节收在开发者入口。

#### REQ-PROXY-011 页面状态可重建

**EARS**：当应用重启或扩展进程被系统回收后再次进入代理页时，系统应重建并展示真实状态。

**验收标准**
- **Given** 之前处于 `connected` 且应用被系统回收，**When** 重新进入页面，**Then** 状态不得直接显示「已连接」，必须先探测扩展与 TUN 真实状态。
- **Given** 配置存在但代理未运行，**Then** 显示 `stopped`。
- [ ] 重建过程不得自动重发订阅请求或重新启动 VPN，除非用户明确操作。

#### REQ-PROXY-012 代理页不阻塞主线程

**EARS**：当代理页执行刷新、状态查询或配置读取时，系统应保证 ArkUI 主线程可继续响应滚动与返回。

**验收标准**
- **Given** 节点数量较大（≥500），**When** 用户滚动列表，**Then** 无超过 200 ms 的主线程卡顿（可主观观察 + 帧率记录）。
- **Given** 用户点击返回，**Then** 立即响应，不等后台请求完成。
- [ ] 任何内核调用不得在 UI 线程同步阻塞（对照基线 §3.8 的 `quickStartSync` 风险）。

### 7.2 VPN 启停与授权

#### REQ-PROXY-013 开启前置校验

**EARS**：当用户开启代理开关时，系统应先校验配置有效性与内核可用性，再进入 `preparing`。

**验收标准**
- **Given** 无有效配置，**Then** 不启动内核、不请求 TUN，保持 `unconfigured` 并提示导入。
- **Given** 配置存在但内核库缺失（安装包不含 `.so`），**Then** 直接进入 `failed`，文案说明「此安装包不包含代理内核」，且不得请求 VPN 授权。
- **Given** 校验通过，**Then** 进入 `preparing` 并开始启动流程。
- [ ] 校验结果与最终状态一致，无「先显示已连接再回退」的闪变。

#### REQ-PROXY-014 首次授权引导

**EARS**：当系统首次需要建立 VPN 连接时，系统应在触发系统授权弹窗之前给出简短说明，并在弹窗后按用户选择继续。

**验收标准**
- **Given** 用户首次开启且从未授权，**Then** 页面先说明「系统将请求允许 HmChat 建立 VPN 连接」，随后由系统弹窗接管。
- **Given** 授权成功，**Then** 继续 `preparing`，不重复弹窗。
- [ ] 提示文案不承诺「不经过系统」或「自动授权」。

#### REQ-PROXY-015 授权拒绝可恢复

**EARS**：若用户在系统授权弹窗中拒绝，则系统应进入 `unauthorized`，并提供可重试入口。

**验收标准**
- **Given** 用户拒绝授权，**Then** 状态为 `unauthorized`，开关回到关闭位，页面说明拒绝原因。
- **Given** 用户再次开启，**Then** 允许重新触发授权流程（不因一次拒绝被永久封锁）。
- [ ] 拒绝后不建立 TUN、不写任何订阅或节点机密到新位置、不进入后台保活。

#### REQ-PROXY-016 准备中具备超时与取消

**EARS**：在 `preparing` 期间，系统应提供可见进度，并在超过既定启动预算时转为 `failed`。

**验收标准**
- **Given** 启动超过配置的超时预算（建议 60 s，最终值待真机标定），**Then** 进入 `failed`，文案说明「启动超时」并提供重试。
- **Given** 用户在准备中点击取消，**Then** 中止启动并释放资源，最终落 `stopped`。
- [ ] 准备中不显示节点「已连接」标记或成功色。

#### REQ-PROXY-017 已连接判定采用三重证据

**EARS**：只有当内核加载成功、TUN fd 有效且路由配置生效时，系统才应进入 `connected`。

**验收标准**
- **Given** 内核初始化返回成功、TUN 建立返回有效 fd、路由/DNS 下发无错误，**Then** 状态为 `connected`。
- **Given** 任一条件不满足，**Then** 状态不得为 `connected`（进入 `preparing` 或 `failed`）。
- **Given** 仅为「RPC 可达」或「扩展进程已启动」，**Then** 不得判定为 `connected`（对照基线 §3.5 的 `init: "ok"` 伪成功）。
- [ ] 状态判定逻辑有可复查的日志/诊断记录（脱敏）。

#### REQ-PROXY-018 关闭与停止收敛

**EARS**：当用户关闭代理时，系统应停止 TUN、停止内核隧道并释放端口，最终进入 `stopped`。

**验收标准**
- **Given** 用户关闭开关，**Then** TUN 关闭、代理失效、既有网络恢复可用（浏览器或 TDLib 可正常联网）。
- **Given** 停止完成，**Then** 状态为 `stopped`，且不再有 RPC 端口监听。
- **Given** 停止过程中某一步失败，**Then** 仍要尽力释放资源，并在状态卡显示「已停止，但存在未释放资源」类明确提示，不得静默。
- [ ] 停止后通知栏不残留「VPN 运行中」通知。

#### REQ-PROXY-019 外部终止时状态同步

**EARS**：当 VPN 被系统或其他入口终止时，系统应把 UI 状态更新为 `stopped` 或 `failed`，不得停留在 `connected`。

**验收标准**
- **Given** 用户在系统设置中关闭该 VPN，**When** 回到 HmChat，**Then** 状态为 `stopped`（或明确的「已被系统停止」）。
- **Given** 扩展进程异常退出，**Then** UI 在有限时间内（建议 ≤10 s）检测到并更新状态。
- [ ] 状态同步失败时不显示旧的成功态。

#### REQ-PROXY-020 后台存活与通知一致

**EARS**：当代理在后台运行时，系统应维持必要的后台存活手段，并使通知内容与实际状态一致。

**验收标准**
- **Given** 代理已连接且应用退到后台，**Then** 在验收时长（建议 ≥10 分钟）内代理保持可用；若被系统回收，需如实记录并显示可恢复提示。
- **Given** 通知存在，**Then** 标题/正文反映真实状态，停止后通知消失。
- [ ] 通知文案不含节点密码、订阅 URL、域名。
- 【待确认】保活应挂在 UI 进程（`dataTransfer` 长时任务）还是扩展自身 `backgroundModes`；两者取舍见 §9。

#### REQ-PROXY-021 扩展崩溃后的有限重启

**EARS**：若扩展进程连续崩溃，系统应按退避策略有限重试，超过预算后停止自动重启并要求用户手动重试。

**验收标准**
- **Given** 扩展崩溃一次，**Then** 在退避后尝试恢复，并在 UI 显示「正在重新连接」。
- **Given** 连续崩溃达到上限（建议 5 次，对齐上游行为），**Then** 停止自动重启，状态为 `failed` 并提供手动重试。
- [ ] 崩溃计数在用户手动重试或成功连接后重置。

#### REQ-PROXY-022 声明缺失时给出明确错误

**EARS**：若安装包缺少 VPN 扩展声明或所需能力，系统应在开启时给出明确不可用提示，而不是静默失败。

**验收标准**
- **Given** 模块未声明 `type: "vpn"` 扩展，**Then** 开启动作返回明确错误，状态为 `failed`，文案说明当前安装包不支持该能力。
- **Given** 系统版本不满足 API 要求，**Then** 提示「当前系统版本不支持」，并禁用开关。
- [ ] 不可用时开关为禁用态并附简短原因，不制造可成功的错觉。

#### REQ-PROXY-023 全局代理影响需提前告知

**EARS**：当用户首次开启全局代理时，系统应说明该代理会影响设备上其他应用的网络。

**验收标准**
- **Given** 首次开启且范围为「全局」，**Then** 展示一次性说明（页面内提示或确认），可被用户关闭后不再重复。
- **Given** 用户选择「仅 HmChat 走代理」，**Then** 提示内容随之变化，不误称「全局」。
- [ ] 说明文案与实际生效范围一致（对照 REQ-PROXY-077 至 082）。

#### REQ-PROXY-024 配置变更触发的重启需用户可见

**EARS**：当用户在连接状态下切换配置或节点并需要重启内核时，系统应显示重启过程并保持可取消/可回滚。

**验收标准**
- **Given** 已连接时切换到另一配置，**Then** 显示「正在应用配置」，期间状态不显示为 `connected`。
- **Given** 应用配置失败，**Then** 回到原配置与原节点，状态为 `connected` 或 `failed`（依原配置是否仍可用），并说明失败原因。
- [ ] 重启不导致重复授权弹窗（除系统要求外）。

#### REQ-PROXY-025 代理与 Telegram 连接互不代偿

**EARS**：当代理不可用时，系统不得以「Telegram 仍可直连」掩盖代理失败，也不得因代理可用而伪造 Telegram 连接成功。

**验收标准**
- **Given** 代理 `failed` 但 TDLib 直连正常，**Then** 代理页仍显示失败；聊天功能正常且不受影响。
- **Given** 代理 `connected` 但 TDLib 认证失败，**Then** Telegram 显示其自身错误，代理页保持已连接事实。
- [ ] 两个状态区互不覆盖、互不复用字段。

#### REQ-PROXY-026 授权与连接状态的可观测记录

**EARS**：当授权或连接状态发生变化时，系统应记录脱敏的状态迁移记录，供问题诊断。

**验收标准**
- **Given** 状态从 `preparing` 变为 `failed`，**Then** 记录时间、来源状态、目标状态、错误码（不含敏感值）。
- **Given** 用户导出诊断信息，**Then** 内容不含订阅 URL、节点密码、域名、消息内容与本机绝对路径。
- [ ] 记录容量有上限并轮转，不无限增长。

### 7.3 订阅导入、更新与删除

#### REQ-PROXY-027 订阅 URL 导入

**EARS**：当用户提交订阅 URL 时，系统应校验格式、去除首尾空白，并在校验通过后开始导入。

**验收标准**
- **Given** 用户输入合法的 `https://` 或 `http://` URL，**Then** 开始导入并显示进行中状态。
- **Given** 输入为空、缺少 scheme、含换行或明显非法字符，**Then** 就地提示格式错误，不发起网络请求。
- **Given** 用户重复提交同一 URL，**Then** 不产生并行重复请求。
- [ ] 输入框不回显已被保存的完整 URL（可显示脱敏形式，如仅域名与末 4 位）。

#### REQ-PROXY-028 订阅 URL 立即进入受保护存储

**EARS**：当订阅导入开始或成功时，系统应把订阅 URL 写入 Asset 或受保护文件，禁止写入 Preferences 明文。

**验收标准**
- **Given** 导入成功，**Then** 订阅 URL 仅存在于受保护存储与内存工作副本中。
- **Given** 检查 Preferences、日志文件、截图与 `artifacts/`，**Then** 均不含完整 URL 或 token。
- [ ] 开发模式下也不得以调试开关绕过该约束。

#### REQ-PROXY-029 订阅解析结果可核查

**EARS**：当订阅内容返回后，系统应解析为可用配置，并向用户展示节点数量与解析结果。

**验收标准**
- **Given** 订阅内容为受支持的 Clash YAML（或受支持的分发格式），**Then** 展示「已导入，包含 N 个节点 / M 个分组」。
- **Given** 内容为空、非 YAML、缺少必要字段或节点数为 0，**Then** 导入失败并说明具体原因，不写入半成品配置。
- **Given** 订阅返回 HTML 错误页或需要登录，**Then** 提示「订阅地址无效或需要认证」，不当作成功。
- 【待确认】是否支持 base64 订阅与内核侧转换（依赖 core 能力），未确认前只承诺 Clash YAML 与「明确不支持」提示。

#### REQ-PROXY-030 订阅字段结构校验

**EARS**：当系统解析订阅配置时，应校验其包含可用代理定义与必要的出站结构，缺项时拒绝导入。

**验收标准**
- **Given** 配置缺少 `proxies` 或 `proxy-groups`，**Then** 拒绝导入并提示配置不完整。
- **Given** 配置含不受支持的协议，**Then** 保留受支持节点并明确告知被忽略的数量与原因。
- [ ] 校验错误信息聚焦用户可理解的原因，不输出解析器堆栈或内部字段路径。

#### REQ-PROXY-031 订阅更新

**EARS**：当用户触发订阅更新时，系统应重新拉取并替换配置，同时保留可回滚的旧版本。

**验收标准**
- **Given** 用户点击「更新」，**Then** 显示更新中状态；成功后刷新节点列表与更新时间。
- **Given** 更新前节点处于选中状态且新配置仍存在同名节点，**Then** 保持该节点选中；若不存在，回退到配置默认策略并提示。
- **Given** 更新失败，**Then** 保留旧配置继续可用，且明确显示失败原因与最后成功更新时间。
- [ ] 更新过程不中断正在进行的代理连接（或明确提示将短暂重启）。

#### REQ-PROXY-032 更新失败不破坏现状

**EARS**：若订阅更新失败，则系统应保持旧配置、旧节点选择与旧连接状态，并显示失败原因。

**验收标准**
- **Given** 网络超时、HTTP 错误、内容解析失败，**Then** 旧配置仍可加载与启动。
- **Given** 连续更新失败，**Then** 不自动无限重试；提供手动重试。
- [ ] 失败不清理本地已保存的配置与凭据。

#### REQ-PROXY-033 删除订阅

**EARS**：当用户删除订阅时，系统应要求确认，并在确认后清理配置、凭据、缓存与日志中的相关引用。

**验收标准**
- **Given** 用户点击删除，**Then** 出现确认弹层，明确作用范围（该订阅及其节点、缓存）。
- **Given** 该订阅为当前生效配置且代理在运行，**Then** 先停止或先提示「将断开代理」，不得直接删文件造成状态不一致。
- **Given** 删除完成，**Then** 列表移除该项，受保护存储中的 URL 与生成配置、缓存、日志引用一并清理。
- [ ] 删除后重新进入页面不残留空节点或幽灵状态。

#### REQ-PROXY-034 订阅列表信息完整

**EARS**：订阅与本地配置列表应展示足够的识别信息，且不泄露机密。

**验收标准**
- **Given** 列表非空，**Then** 每项显示名称、来源类型（订阅/本地）、节点数、最近更新时间、当前是否生效。
- **Given** 该项上次导入/更新失败，**Then** 显示失败标记与简述。
- [ ] 名称默认取配置名或域名级摘要；不展示完整 URL 或 token。

#### REQ-PROXY-035 多配置并存与生效选择

**EARS**：当存在多个配置时，系统应允许用户指定唯一生效配置，并明确标出当前生效项。

**验收标准**
- **Given** 存在两个以上配置，**Then** 同一时刻只有一个被标记为生效。
- **Given** 用户切换生效配置，**Then** 触发 REQ-PROXY-024 的重启/应用流程。
- [ ] 非生效配置的节点不参与当前节点选择与测速结果展示。

#### REQ-PROXY-036 订阅请求的网络与隐私边界

**EARS**：当系统拉取订阅时，应通过受控网络路径请求，并在失败提示中隐藏完整 URL。

**验收标准**
- **Given** 订阅拉取成功或失败，**Then** 错误提示只显示域名级信息，不含 token 与完整路径。
- **Given** 用户开启了代理，**Then** 订阅拉取行为符合产品声明（是否需要经代理拉取须明示，不得悄悄直连）。
- [ ] 不在日志中记录请求头、查询参数或响应正文中的凭据。

#### REQ-PROXY-037 订阅体积上限

**EARS**：当订阅内容超过既定上限时，系统应拒绝导入并给出可操作提示。

**验收标准**
- **Given** 内容超过上限（建议 8 MB，最终值待标定），**Then** 中止导入并提示「订阅内容过大」。
- **Given** 内容接近上限但有效，**Then** 正常导入且页面不卡死。
- [ ] 上限与实际可用内存匹配，不因一次导入导致应用被杀。

#### REQ-PROXY-038 定时自动更新默认关闭

**EARS**：系统默认不应自动定时更新订阅；如后续提供，必须为显式开启且可关闭。

**验收标准**
- **Given** 首次安装，**Then** 无自动更新定时任务，无后台网络请求。
- **Given** 未来版本提供自动更新，**Then** 默认关闭、周期可见、可随时关闭，且失败不改变现有配置。
- [ ] 本 MVP 不实现自动定时更新（列入非目标），文档不得宣称已支持。

### 7.4 本地 Clash YAML 导入

#### REQ-PROXY-039 通过系统文件选择器导入

**EARS**：当用户选择「导入本地配置」时，系统应调用系统文件选择器，只接受可读取的文本配置文件。

**验收标准**
- **Given** 用户点击导入入口，**Then** 打开官方系统文件选择器（不自定义文件浏览界面）。
- **Given** 用户取消选择，**Then** 返回代理页，状态与配置不变，无错误弹窗。
- **Given** 所选文件不可读或无权限，**Then** 显示「无法读取该文件」并保持原状。
- [ ] 选择器不请求与应用功能无关的权限。

#### REQ-PROXY-040 导入前校验文件

**EARS**：当用户选定文件后，系统应在写入前校验文件大小、编码与 YAML 结构。

**验收标准**
- **Given** 文件超过体积上限，**Then** 拒绝导入并提示上限。
- **Given** 文件非 UTF-8 或解析失败，**Then** 提示「配置格式无法解析」，不写入任何文件。
- **Given** 缺少代理定义或必要结构，**Then** 拒绝并说明缺失项。
- [ ] 校验在同一流程内完成，不留下临时半成品文件。

#### REQ-PROXY-041 导入命名与冲突处理

**EARS**：当导入成功时，系统应为配置生成可读名称；若同名配置已存在，应区分而不是覆盖。

**验收标准**
- **Given** 配置内声明了名称，**Then** 默认使用该名称（做长度与敏感字符处理）。
- **Given** 名称已存在，**Then** 追加序号或要求用户确认替换，不得静默覆盖已有配置。
- [ ] 名称长度受限，列表行不因超长名称破坏布局。

#### REQ-PROXY-042 导入内容存入受保护位置

**EARS**：当本地配置文件导入成功后，系统应把包含凭据的完整配置存入仅扩展进程可读的受保护位置。

**验收标准**
- **Given** 导入成功，**Then** 完整 YAML（含密码 / UUID）不位于 Preferences、公共目录或可被其他应用读取的位置。
- **Given** 检查备份配置，**Then** 代理配置与规则缓存不进入系统备份/云备份范围。
- [ ] 导入后临时文件（若存在）被清理。

#### REQ-PROXY-043 非法配置不改变现状

**EARS**：若本地配置导入失败，则系统应保持原有配置、节点选择与运行状态不变。

**验收标准**
- **Given** 导入过程中任一步失败，**Then** 原生效配置仍可启动，列表内容不变。
- **Given** 失败发生时代理在运行，**Then** 连接不受影响。
- [ ] 失败提示包含可操作的下一步（重新选择文件 / 检查格式）。

#### REQ-PROXY-044 导入后不自动切换生效配置

**EARS**：当导入成功时，系统应把新配置加入列表；仅当不存在其他配置时才自动设为生效，否则是否立即切换由用户确认。

**验收标准**
- **Given** 已有生效配置且代理在运行，**When** 导入新配置，**Then** 新配置标记为「未生效」，当前连接不中断。
- **Given** 无其他配置，**Then** 新配置自动成为生效配置，但代理仍保持 `stopped`（不自动启动）。
- [ ] 页面明确提示「已导入，是否立即使用」类动作。

#### REQ-PROXY-045 禁止任意路径读取

**EARS**：系统应只读取用户通过系统选择器明确授权的文件，不接受任意路径或目录遍历输入。

**验收标准**
- **Given** 任何外部传入的路径字符串（深层链接、Intent 参数、文件名），**Then** 不作为文件读取依据。
- **Given** 需要引用沙箱内文件，**Then** 路径必须限制在应用沙箱根目录内并做规范化校验。
- [ ] 拒绝 `..`、绝对路径越界与符号链接逃逸。

### 7.5 节点列表与选择

#### REQ-PROXY-046 节点列表展示

**EARS**：当配置加载完成时，系统应展示代理组与节点，并标注当前选中项与延迟信息。

**验收标准**
- **Given** 配置含 3 个分组、50 个节点，**Then** 列表按分组展示，组内节点可滚动查看，当前选中项有明确标记。
- **Given** 节点名称重复，**Then** 通过分组或附加信息区分，不出现无法分辨的两个同名项。
- **Given** 某节点在当前配置下不可用（协议不支持/缺少字段），**Then** 置灰并说明原因，不允许选中。
- [ ] 列表不使用固定高度裁切长名称。

#### REQ-PROXY-047 节点选择生效

**EARS**：当用户选择某个节点时，系统应把选择下发给内核并确认生效后才更新选中标记。

**验收标准**
- **Given** 用户点击节点，**Then** 显示「正在切换」，成功后选中标记移到该节点。
- **Given** 内核返回失败，**Then** 选中标记回滚到原节点，并显示失败原因。
- **Given** 代理未运行，**Then** 选择只更新配置并持久化，不显示「已连接」。
- [ ] 选中标记不得在未收到内核确认前提前更新（避免「看起来切了其实没切」）。

#### REQ-PROXY-048 选择持久化与重启恢复

**EARS**：当应用重启或配置重新加载时，系统应恢复用户上次的有效节点选择。

**验收标准**
- **Given** 用户上次选中节点 A 且配置未变，**When** 重启后进入页面，**Then** 节点 A 仍为选中。
- **Given** 更新后的配置不再包含节点 A，**Then** 回退到配置默认策略并明确提示。
- [ ] 恢复过程不自动启动代理。

#### REQ-PROXY-049 自动选择组的只读呈现

**EARS**：当分组为自动选择类型（如自动测速、故障转移）时，系统应展示其当前实际出口节点，但不提供规则编辑。

**验收标准**
- **Given** 分组为自动类型，**Then** 显示「自动」标识与当前实际使用的节点（来自内核事实）。
- **Given** 用户尝试手动介入自动组，**Then** 不提供节点级手动选择（或以「临时指定」明确表达，且不改变规则）。
- [ ] 不提供新建分组、编辑策略、正则匹配等规则编辑能力（非目标）。

#### REQ-PROXY-050 节点信息不泄漏凭据

**EARS**：节点列表与详情应只展示识别信息，不展示密码、UUID、私钥或完整服务器参数。

**验收标准**
- **Given** 节点详情，**Then** 可展示名称、协议类型、分组、延迟、可用性。
- **Given** 任何界面状态（含错误、复制、分享、截图），**Then** 不含密码 / UUID / 私钥明文。
- [ ] 节点名称若由订阅下发且疑似含凭据，按普通文本展示但不写入日志。

#### REQ-PROXY-051 无可用节点时的明确状态

**EARS**：若配置解析后没有任何可用节点，系统应阻止启动并说明原因。

**验收标准**
- **Given** 节点数为 0，**Then** 开关不可用，提示「当前配置没有可用节点」。
- **Given** 所有节点均不可用，**Then** 允许查看原因列表，不静默失败。
- [ ] 该状态归入 `unconfigured` 或 `failed`（依是否存在配置），不进入 `connected`。

#### REQ-PROXY-052 节点切换的连接影响可预期

**EARS**：当用户切换节点时，系统应说明是否会导致连接短暂中断，并尽量不中断 TDLib 会话。

**验收标准**
- **Given** 已连接状态下切换节点，**Then** 显示切换过程；若导致 TDLib 重连，明确提示「网络已切换」。
- **Given** 切换完成，**Then** 聊天可用性与切换前一致（消息可正常收发）。
- [ ] 切换不触发账户重新登录、不清空草稿。

#### REQ-PROXY-053 节点列表刷新

**EARS**：当配置或内核状态变化时，系统应提供刷新方式并保持滚动位置合理。

**验收标准**
- **Given** 更新订阅后，**Then** 节点列表自动刷新且当前节点若仍存在保持选中。
- **Given** 用户手动刷新，**Then** 显示进行中状态，刷新失败保留旧列表。
- [ ] 刷新不重置用户滚动位置到顶部（除非列表结构变化无法映射）。

#### REQ-PROXY-054 大量节点下的可用性

**EARS**：当节点数量达到数百时，系统应保持列表滚动与交互可用。

**验收标准**
- **Given** 节点数 ≥500，**Then** 首屏渲染 ≤1 s，滚动无长时间白屏。
- **Given** 用户搜索或筛选节点名（若提供），**Then** 结果实时更新且不阻塞滚动。
- [ ] 不使用一次性全量渲染导致内存异常。

#### REQ-PROXY-055 删除配置时节点区同步

**EARS**：当生效配置被删除或替换时，节点区应同步清空或刷新，不展示过期节点。

**验收标准**
- **Given** 生效配置被删除，**Then** 节点区回到空态，选中节点清空。
- **Given** 切换生效配置，**Then** 节点区只展示新配置的节点。
- [ ] 不残留上一配置的延迟数据与选中标记。

#### REQ-PROXY-056 节点选择与代理范围互不影响

**EARS**：当用户切换「全局 / 仅 HmChat」范围时，系统应保持节点选择不变。

**验收标准**
- **Given** 已选节点 A，**When** 切换范围，**Then** 节点 A 仍为选中。
- **Given** 范围切换导致内核重启，**Then** 重启后恢复节点 A 或明确说明回退原因。
- [ ] 两个设置项的持久化互不覆盖。

### 7.6 延迟测速

#### REQ-PROXY-057 单节点测速

**EARS**：当用户对某节点触发测速时，系统应执行延迟探测并在完成或超时后更新该节点延迟。

**验收标准**
- **Given** 用户点击测速，**Then** 该节点显示「测速中」，完成后显示毫秒值或失败标记。
- **Given** 测速超时，**Then** 显示「超时」而不是 `0 ms` 或空白。
- **Given** 探测返回非零错误，**Then** 显示失败并允许重试。
- [ ] 测速结果不得被当作「连接已建立」的证据。

#### REQ-PROXY-058 批量测速的并发与顺序

**EARS**：当用户触发批量测速时，系统应限制并发数量，并按可预期的顺序逐批完成。

**验收标准**
- **Given** 用户点击「全部测速」，**Then** 逐项出现结果，界面保持可滚动、可返回。
- **Given** 节点数量较多，**Then** 并发不超过设定上限（建议 4–8，最终值待真机标定），不出现网络风暴。
- [ ] 批量测速可被用户取消，取消后已得结果保留、未完成项回到未测状态。

#### REQ-PROXY-059 测速结果仅为参考值

**EARS**：系统应把测速结果限定为展示参考，不作为持久化的连通性保证。

**验收标准**
- **Given** 节点延迟为 30 ms 但实际不可用，**When** 用户选择该节点，**Then** 仍以真实连接结果为准并显示失败原因。
- **Given** 应用重启，**Then** 上次测速值可标记为「历史」或不展示，不冒充实时值。
- [ ] 不在测速结果旁展示「可用 / 最优」等未经真实连接验证的承诺性结论。

#### REQ-PROXY-060 测速不阻塞关键路径

**EARS**：当测速进行时，系统应保证启停、返回与页面滚动不受阻塞。

**验收标准**
- **Given** 批量测速进行中，**When** 用户点击返回，**Then** 页面立即返回，测速在后台收敛或取消。
- **Given** 测速进行中，**Then** 主线程无长时间阻塞，不延迟 protect 回执等关键处理。
- [ ] 测速不与其他内核关键调用共用会阻塞的同步通道。

#### REQ-PROXY-061 测速网络路径合规

**EARS**：当执行测速时，系统应保证探测行为符合代理链路设定，不绕过用户已开启的代理造成额外直连。

**验收标准**
- **Given** 代理已开启，**Then** 测速请求按产品声明的路径执行（经内核或明确的直连策略），并在文档中说明。
- **Given** 代理未开启，**Then** 测速仍可工作，但需说明其为「控制器直连」或明确不可用，不得静默。
- [ ] 不向第三方地址发送可识别的用户标识或订阅信息。

#### REQ-PROXY-062 测速中的错误不使用统一「未知」

**EARS**：若测速失败，系统应区分超时、拒绝、协议错误、配置错误等可区分原因。

**验收标准**
- **Given** 不同失败原因，**Then** 提供至少「超时」「连接被拒绝」「协议不支持」三类可区分提示。
- **Given** 无法区分，**Then** 显示「测速失败」并提供查看详情，不伪造数值。
- [ ] 错误明细不含节点密码与完整服务器地址。

#### REQ-PROXY-063 测速结果可清除

**EARS**：当配置更新或删除时，系统应清除对应的测速结果。

**验收标准**
- **Given** 订阅更新，**Then** 旧节点的延迟值不沿用到新节点（除可确认为同一节点）。
- **Given** 删除配置，**Then** 对应测速结果一并清除。
- [ ] 清除后界面不显示过期毫秒值。

#### REQ-PROXY-064 测速入口可达性

**EARS**：代理页应提供单节点测速与批量测速入口，并在不可用时给出原因。

**验收标准**
- **Given** 配置存在但代理未启动，**Then** 测速入口按产品策略可用或明确禁用（须与 REQ-PROXY-061 一致）。
- **Given** 无节点，**Then** 测速入口禁用并有简短原因。
- [ ] 入口具备无障碍描述（如「测试该节点延迟」）。

### 7.7 状态机与错误、重试

#### REQ-PROXY-065 状态机单一真值

**EARS**：系统应以 §6 状态机作为代理状态的唯一来源，并在非法迁移时拒绝并记录。

**验收标准**
- **Given** 当前 `unconfigured`，**When** 收到「已连接」事件，**Then** 拒绝该迁移并记录异常。
- **Given** 任一时刻，**Then** 界面只展示一个确定状态，不出现两个状态的矛盾文案。
- [ ] 状态迁移实现可被单元测试覆盖（纯状态逻辑置于可测试模块）。

#### REQ-PROXY-066 状态文案映射一致

**EARS**：每个状态应映射到唯一的用户文案与视觉语义，且与 §6.1 一致。

**验收标准**
- **Given** 六个状态，**Then** 文案分别为「尚未导入配置」「未获得 VPN 授权」「正在启动代理…」「已连接」「已停止」「启动失败」。
- **Given** 深色与浅色主题，**Then** 状态色对比度满足可读性要求。
- [ ] 文案不出现内部状态标识（如 `preparing`）。

#### REQ-PROXY-067 错误码与可操作建议

**EARS**：当发生错误时，系统应给出用户可理解的错误码或分类，并附带下一步建议。

**验收标准**
- **Given** 内核缺失，**Then** 提示「此安装包不包含代理内核」并建议更换完整安装包。
- **Given** 配置无效，**Then** 建议重新导入或更新订阅。
- **Given** 端口/鉴权失败，**Then** 提示「内部服务连接失败」并建议重试或重启应用。
- [ ] 不把 SDK 路径、ABI、二进制名称作为主提示文案。

#### REQ-PROXY-068 手动重试与退避

**EARS**：当状态为 `failed` 时，系统应提供手动重试；自动重试必须有次数与退避上限。

**验收标准**
- **Given** 用户点击「重试」，**Then** 重新执行启动流程并显示 `preparing`。
- **Given** 自动重试达到上限，**Then** 停止自动重试，仅保留手动入口。
- [ ] 重试不重复写入配置或重复请求授权（除系统要求）。

#### REQ-PROXY-069 错误不静默

**EARS**：任何失败路径都不得只写日志；至少要在页面上留下可见状态或提示。

**验收标准**
- **Given** 扩展启动失败、RPC 认证失败、protect 失败、通知失败，**Then** 分别有对应的用户可见或开发者可见记录，且关键失败（影响代理可用性）必须用户可见。
- **Given** 仅影响体验的次要失败（如通知发布失败），**Then** 至少在诊断记录中可见。
- [ ] 不以「成功返回空字符串 / `true` / `0`」表示失败（对照基线 §4.7 的静默失败清单）。

#### REQ-PROXY-070 错误信息去敏

**EARS**：所有错误提示与日志应去除订阅 URL、节点密码、UUID、域名、消息内容与本机路径。

**验收标准**
- **Given** 订阅拉取失败，**Then** 提示仅含域名级信息。
- **Given** 内核报错含配置片段，**Then** 展示前做裁剪与替换，不显示凭据。
- [ ] 使用统一脱敏函数，不依赖各处人工注意。

#### REQ-PROXY-071 代理状态与 Telegram 状态隔离

**EARS**：系统应把代理状态与 `telegram.ready`、连接状态、账户状态分别建模。

**验收标准**
- **Given** Telegram 未登录，**Then** 代理仍可独立启停（若产品允许），且两个状态区互不覆盖。
- **Given** 退出账号，**Then** 代理状态不受影响，代理页仍可访问（若入口保留）。
- [ ] 代码层面不复用同一 phase 枚举或错误字段。

#### REQ-PROXY-072 无配置的失败不可伪装成授权问题

**EARS**：当失败由配置缺失或配置无效引起时，系统应指向配置问题，而不是提示授权失败。

**验收标准**
- **Given** 无配置，**Then** 状态为 `unconfigured`，提示导入，不请求 VPN 授权。
- **Given** 配置损坏，**Then** 提示重新导入，不显示「未授权」。
- [ ] 错误分类有明确映射表并可在测试中验证。

#### REQ-PROXY-073 长时运行的状态一致性

**EARS**：当代理长时间运行（≥30 分钟）时，系统应保持状态与真实连接一致。

**验收标准**
- **Given** 连续运行 30 分钟，**Then** 状态仍为 `connected` 且流量可用；若中途被系统回收，状态如实变更。
- **Given** 网络切换（Wi-Fi ↔ 蜂窝），**Then** 状态与提示反映实际可用性，不长期停留在错误状态。
- [ ] 后台/前台切换不重复触发授权或重建 TUN。

#### REQ-PROXY-074 状态迁移记录可追溯

**EARS**：系统应记录状态迁移序列，支持问题定位且不含敏感信息。

**验收标准**
- **Given** 一次完整启停，**Then** 可导出迁移序列（时间、状态、错误码），条数与实际一致。
- **Given** 导出内容进入公开仓库前，**Then** 可直接通过既有隐私检查（无敏感字段）。
- [ ] 记录文件有大小上限与轮转策略。

#### REQ-PROXY-075 取消与超时的资源一致性

**EARS**：当启动被取消或超时后，系统应确保不残留 TUN、内核线程或端口占用。

**验收标准**
- **Given** 启动超时进入 `failed`，**Then** 再次重试可成功，不因残留资源失败。
- **Given** 用户取消启动，**Then** 系统中不存在该 VPN 连接（系统设置中不可见活动 VPN）。
- [ ] 连续 10 次取消/失败循环后仍可正常启动。

#### REQ-PROXY-076 诊断入口受控

**EARS**：若提供开发者诊断入口，应默认隐藏且导出内容脱敏。

**验收标准**
- **Given** 普通用户，**Then** 界面不出现内核路径、Action 名称、原始 JSON。
- **Given** 打开诊断，**Then** 可见内核版本、状态迁移、错误码、protect 计数（脱敏）。
- [ ] 诊断导出文件不自动上传，不含真实账号标识。

### 7.8 代理范围（默认全局 / 仅 HmChat）

#### REQ-PROXY-077 默认全局代理

**EARS**：当用户首次开启代理且未修改范围设置时，系统应使用「全局代理所有应用」作为默认范围。

**验收标准**
- **Given** 首次安装并开启，**Then** 范围为「全局」，页面明确展示这一点。
- **Given** 全局模式生效，**Then** 设备上其他应用的网络流量按 TUN 路由经代理（以可观察的连通性差异与内核连接记录验证）。
- [ ] 全局模式不使用分应用白名单（`trustedApplications`）作为默认实现。

#### REQ-PROXY-078 「仅 HmChat 走代理」开关

**EARS**：系统应提供「仅 HmChat 走代理」开关，使用户可把代理限定在本应用范围内。

**验收标准**
- **Given** 用户开启该开关，**Then** 范围为「仅 HmChat」，其他应用按直连处理（或不被纳入代理路由）。
- **Given** 开关关闭，**Then** 回到「全局」。
- [ ] 该开关不是分应用列表，不提供逐应用勾选（非目标）。

#### REQ-PROXY-079 范围切换需要明确生效与重启

**EARS**：当范围切换需要重建 TUN 或重载配置时，系统应显示过程并在完成后确认新范围。

**验收标准**
- **Given** 代理运行中切换范围，**Then** 显示「正在应用网络范围」，期间状态不为 `connected`。
- **Given** 切换完成，**Then** 页面显示实际生效范围，且与开关状态一致。
- [ ] 切换不改变所选节点与订阅。

#### REQ-PROXY-080 范围切换失败回滚

**EARS**：若范围切换失败，系统应恢复到切换前的范围与连接状态，并说明失败原因。

**验收标准**
- **Given** 切换失败，**Then** 原范围仍生效（或代理安全停止），开关回滚到原值。
- **Given** 回滚后，**Then** 页面文案与实际一致，不出现开关显示「仅 HmChat」而实际全局生效。
- [ ] 失败不导致设备完全断网（若断网，必须给出明确恢复指导）。

#### REQ-PROXY-081 范围设置持久化

**EARS**：范围选择应跨重启保留，且与「VPN 是否开启」分开存储。

**验收标准**
- **Given** 用户选择「仅 HmChat」后重启应用，**Then** 范围仍为「仅 HmChat」，代理保持 `stopped`。
- **Given** 清除配置，**Then** 范围设置按产品定义保留或重置，行为在文档中说明。
- [ ] 范围设置不写入演示数据快照。

#### REQ-PROXY-082 「仅 HmChat」实现的降级说明

**EARS**：若平台或内核不支持可靠的「仅 HmChat」实现，系统应明确标注该模式的可用性，不得假装生效。

**验收标准**
- **Given** 实现依赖的分应用能力在真机上表现为不可预期（如被屏蔽应用直接断网，见基线 §4.8），**Then** 该模式在对应设备上标记为不可用或实验性，并在开启前提示。
- **Given** 用户开启实验性模式，**Then** 页面持续显示该状态标识。
- [ ] 未通过真机验证前，README 与页面不得宣称该模式已全面可用。
- 【待确认】实现路径（VPN 分应用名单 / TDLib 内置代理 / 内核分流规则）与真机语义。

### 7.9 持久化与安全

#### REQ-PROXY-083 敏感数据存储介质

**EARS**：系统应把订阅 URL、节点密码、UUID、私钥等凭据存入 HarmonyOS Asset 或仅本应用可读的受保护文件。

**验收标准**
- **Given** 导入订阅或本地配置，**Then** 凭据位于 Asset（建议新别名 `harlgram.proxy.v1`）或扩展沙箱内的受保护文件。
- **Given** 读取 Preferences（`harlgram_local_v1`、`harlgram_appearance_v1`）与任何明文配置，**Then** 不含上述凭据。
- **Given** 多账户场景，**Then** 代理凭据不与 Telegram 凭据共用同一 alias 或同一 JSON 结构。
- [ ] Asset 单条 secret 容量不足以容纳整份订阅时，只存 URL 与索引，完整配置放受保护文件（见 §9 待确认）。

#### REQ-PROXY-084 禁止明文与非受保护位置

**EARS**：系统不得把代理凭据写入 Preferences、日志、截图、公开 artifacts、崩溃报告或公共目录。

**验收标准**
- **Given** 完成一次导入—启停—删除全流程，**Then** 全量检索应用沙箱与 `artifacts/`，无订阅 URL 或节点密码明文。
- **Given** 用户复制界面文本，**Then** 复制内容不含凭据。
- [ ] 该检查作为验收步骤执行，不依赖 `.gitignore` 兜底。

#### REQ-PROXY-085 生成配置的存放与备份排除

**EARS**：系统应把内核加载用的完整配置放在扩展进程可访问的沙箱位置，并排除在系统备份之外。

**验收标准**
- **Given** 配置已生成，**Then** 文件位于应用沙箱内且不随 `backup` 扩展导出。
- **Given** 检查 `backup_config` 相关规则，**Then** 代理配置目录与规则缓存被明确排除。
- [ ] 该目录不包含可用于恢复用户消息的 Telegram 数据。

#### REQ-PROXY-086 删除即清理

**EARS**：当用户删除配置或关闭并清除代理数据时，系统应删除对应的凭据、生成配置、缓存与日志引用。

**验收标准**
- **Given** 删除订阅/配置，**Then** Asset 条目、生成配置文件、测速缓存与临时文件均被删除。
- **Given** 删除完成，**Then** 重新导入同名配置不会复用旧凭据。
- [ ] 删除失败有可见提示，不静默残留。

#### REQ-PROXY-087 内存中凭据的最小化与释放

**EARS**：系统应尽量减少凭据在内存中的副本，并在不再需要时及时释放。

**验收标准**
- **Given** 页面未展示凭据，**Then** 内存中不长期保留完整订阅正文。
- **Given** 关闭代理页或切换配置，**Then** 临时副本被释放，不残留于全局单例。
- [ ] 日志与错误对象不持有凭据字符串引用（避免被打印）。

#### REQ-PROXY-088 截图与公开素材去敏

**EARS**：当生成截图或公开素材时，系统或流程应确保不含订阅地址、节点名以外的敏感信息与个人信息。

**验收标准**
- **Given** 代理页截图用于公开文档，**Then** 节点名、服务器地址、账号信息已脱敏或使用虚构配置。
- **Given** 公开图片登记，**Then** 同时更新 `config/public-assets.json` 并记录哈希。
- [ ] 原始截图只进入忽略目录。

#### REQ-PROXY-089 多账户与账户切换隔离

**EARS**：当用户切换或退出 Telegram 账户时，系统不应重建或重置代理状态与凭据。

**验收标准**
- **Given** 用户在已连接状态下切换账户，**Then** VPN 保持运行，节点选择不变。
- **Given** 退出账号，**Then** 代理配置不被删除；若产品允许，代理可继续运行。
- [ ] 账户切换不触发重复的 VPN 授权弹窗。

#### REQ-PROXY-090 会话 token 与端口轮换

**EARS**：系统应在每次启动代理会话时生成新的通信 token 与端口，不复用固定值。

**验收标准**
- **Given** 连续两次启动，**Then** 端口与 token 均不同。
- **Given** 旧 token 被再次使用，**Then** 连接被拒绝并记录。
- [ ] token 不出现在日志、通知或页面文案中。

#### REQ-PROXY-091 文件访问边界

**EARS**：系统应限制代理配置读写路径在应用沙箱内，并拒绝越界路径。

**验收标准**
- **Given** 任何来自外部输入的路径，**Then** 经规范化后必须位于允许根目录内。
- **Given** 尝试通过符号链接或 `..` 越界，**Then** 拒绝并记录。
- [ ] 内核工作目录与 ArkTS 侧配置根保持同一 `files` 根，避免路径拒绝弹窗（对照基线 §4.2）。

#### REQ-PROXY-092 崩溃与诊断数据不含机密

**EARS**：当发生崩溃或导出诊断数据时，系统应确保内容不含订阅 URL、节点凭据与消息正文。

**验收标准**
- **Given** 崩溃日志，**Then** 不含完整配置文本或请求 URL。
- **Given** 用户导出诊断包，**Then** 内容包括状态迁移、错误码、内核版本，不包含凭据与消息。
- [ ] 崩溃转储不进入公开仓库或工单系统。

#### REQ-PROXY-093 界面不回显凭据

**EARS**：系统界面应以脱敏形式展示配置来源，不提供凭据明文查看。

**验收标准**
- **Given** 订阅项，**Then** 显示名称或域名级摘要，不显示 token。
- **Given** 节点详情，**Then** 不提供「显示密码」能力。
- [ ] 任何「复制配置」类能力若存在，必须明确标注风险并避免自动剪贴敏感内容。

### 7.10 日志与隐私

#### REQ-PROXY-094 日志分级与默认级别

**EARS**：系统应使用分级日志，默认级别不输出内核详细请求信息。

**验收标准**
- **Given** 默认安装，**Then** 仅输出状态迁移、错误码与关键计数。
- **Given** 提高日志级别，**Then** 仍需脱敏，且该开关仅在开发者入口可见。
- [ ] 发布构建不默认开启调试日志。

#### REQ-PROXY-095 日志字段白名单

**EARS**：系统应通过白名单方式记录日志字段，避免整段配置或事件 JSON 直接落盘。

**验收标准**
- **Given** 任一日志条目，**Then** 只包含时间、模块、级别、错误码、状态名、计数等白名单字段。
- **Given** 内核事件含域名/节点名，**Then** 落盘前移除或哈希化。
- [ ] 不记录完整 Action JSON、完整 VpnOptions、完整订阅正文。

#### REQ-PROXY-096 内核日志轮转与上限

**EARS**：当内核产生标准输出/错误时，系统应写入受控日志文件并限制大小与保留数量。

**验收标准**
- **Given** 长时间运行，**Then** 日志文件不超过设定上限（建议单文件 ≤5 MB，保留 ≤2 份）。
- **Given** 日志轮转，**Then** 旧文件被删除而非无限积累。
- [ ] 日志目录位于沙箱内且不进入备份与公开产物。

#### REQ-PROXY-097 公开 artifacts 与提交纪律

**EARS**：当提交源码、文档或日志样例时，系统/流程应确认不含真实订阅、节点、域名与个人信息。

**验收标准**
- **Given** 提交前检查完整暂存区，**Then** 无真实凭据、真实订阅 URL、真实节点地址、账号标识与本机绝对路径。
- **Given** 示例配置，**Then** 使用虚构数据或占位符。
- [ ] 发现泄漏时先移出暂存区并脱敏，再重新检查。

#### REQ-PROXY-098 事件流转发最小化

**EARS**：系统向 UI 转发内核事件时，应只发送界面需要的字段，不转发完整事件对象。

**验收标准**
- **Given** 内核产生流量/连接事件，**Then** UI 只收到聚合流量、状态变化、必要计数。
- **Given** 事件含域名或目标地址，**Then** UI 默认不展示，也不写入日志。
- [ ] UI 侧不缓存原始事件 JSON。

#### REQ-PROXY-099 截断与脱敏的一致性

**EARS**：系统对任何日志截断操作应保证截断后仍不泄露凭据前缀。

**验收标准**
- **Given** 错误信息被截断到固定长度，**Then** 截断不导致 URL 或密码的可识别片段保留。
- **Given** 需要展示上下文，**Then** 先脱敏再截断。
- [ ] 截断长度与脱敏规则有统一实现。

### 7.11 进程隔离、通信安全与 protect

#### REQ-PROXY-100 主进程不加载内核

**EARS**：系统应保证 Telegram 主进程不加载代理内核库，仅 VPN 扩展进程加载。

**验收标准**
- **Given** 应用正常启动且未开启代理，**Then** 主进程已加载库列表中不含内核 `.so`。
- **Given** 主进程内存与启动时间，**Then** 与未集成代理的基线相比无明显回归（建议启动时间增幅 ≤10%，需记录实测）。
- [ ] TDLib 与内核不在同一进程初始化。

#### REQ-PROXY-101 扩展进程代码隔离与模块禁用

**EARS**：VPN 扩展进程内的代码应与 UI 侧服务保持文件级隔离，且不得引用被 SDK 禁用的模块。

**验收标准**
- **Given** 扩展进程代码，**Then** 不 import `contacts` / `geo` / `audio` / `camera` / `call` / `sim` / `sms` 相关模块。
- **Given** 扩展代码，**Then** 不 import `TelegramService`、`MediaNetworkMonitor` 等 UI 侧模块。
- **Given** 需要网络类型信息，**Then** 通过 RPC 向 UI 侧请求，而不是在扩展内直接读取被禁模块。
- [ ] 该约束以真实 SDK 26 编译 + 静态检索双重复核。

#### REQ-PROXY-102 RPC 必须鉴权

**EARS**：当 UI 进程与扩展进程建立通信时，系统应要求首帧携带本次会话 token，校验失败即断开。

**验收标准**
- **Given** 未携带 token 或 token 错误的连接，**Then** 无法调用任何方法、无法收到任何推送。
- **Given** token 正确，**Then** 建立会话；校验使用常数时间比较。
- **Given** 校验失败，**Then** 断开并记录（不含 token 内容）。
- [ ] 不沿用固定端口 47471 的无鉴权模式。

#### REQ-PROXY-103 端口不可预测与协商

**EARS**：系统应使用随机端口或等价机制，使 UI 进程通过受保护通道获知实际端口。

**验收标准**
- **Given** 每次启动，**Then** 监听端口随机且不落在已知固定值。
- **Given** 端口被占用，**Then** 重新选择端口并成功建立会话，或明确失败。
- **Given** 其他进程尝试连接，**Then** 因缺少 token 而无法获得服务。
- [ ] 端口与 token 的传递通道不使用明文公共文件。

#### REQ-PROXY-104 帧与连接限制

**EARS**：系统应限制单帧大小、并发连接数与请求速率，超限即拒绝并断开。

**验收标准**
- **Given** 单帧超过上限（建议 1 MB），**Then** 连接被断开且不造成内存持续增长。
- **Given** 并发连接超过上限（建议 ≤4），**Then** 拒绝新连接。
- **Given** 短时间高频请求，**Then** 触发限流并返回明确错误。
- [ ] 无换行的大帧不会导致缓冲区无限增长。

#### REQ-PROXY-105 protect 队列容量与可靠投递

**EARS**：系统应使用独立的 protect 通道与足够容量，保证代理自身出站 socket 在连接前完成保护。

**验收标准**
- **Given** 高并发建连（建议压测 ≥50 并发），**Then** 无 protect 请求因队列满被丢弃。
- **Given** 队列短暂拥塞，**Then** 系统阻塞重试或明确等待，而不是直接放行未保护的 socket。
- [ ] 队列容量建议 ≥64，最终值以压测结果确定。

#### REQ-PROXY-106 protect 超时与失败可观测

**EARS**：当 protect 未在超时内完成或返回失败时，系统应记录计数与原因，并使关键失败对用户或开发者可见。

**验收标准**
- **Given** protect 超时（建议 3 s），**Then** 计数加一，并在诊断中可见。
- **Given** 持续出现 protect 失败，**Then** 页面或诊断提示「网络保护异常」，并提供恢复建议（停止后重试）。
- [ ] 不允许「失败仍当作成功」的静默放行（对照基线 §4.5）。

#### REQ-PROXY-107 代理自身流量环路防护

**EARS**：系统应确保代理自身的出站连接不被本机 TUN 再次捕获。

**验收标准**
- **Given** 代理运行 10 分钟并持续产生流量，**Then** 无环路特征错误（如反复「拒绝回环」类错误）。
- **Given** 本机回环地址流量（如 `127.0.0.0/8`），**Then** 不被纳入 TUN 路由，本地回环服务继续可用。
- [ ] 环路防护不依赖单一机制，至少有 protect 与路由排除两道保障。

#### REQ-PROXY-108 停止后的收敛与进程回收

**EARS**：当代理停止或扩展空闲时，系统应关闭监听端口并释放内核资源。

**验收标准**
- **Given** 用户停止代理，**Then** RPC 端口不再监听，重连不会被接受。
- **Given** 扩展长时间无会话，**Then** 在空闲超时后释放资源（或明确保留，并在文档说明）。
- [ ] 停止后再次开启可正常建立新会话与新 token。

#### REQ-PROXY-109 内核故障不影响 Telegram

**EARS**：当内核崩溃或扩展进程异常退出时，系统应保证 Telegram 主进程与 TDLib 继续可用。

**验收标准**
- **Given** 人为触发内核异常，**Then** 应用不崩溃、消息收发与页面导航正常。
- **Given** 扩展退出，**Then** UI 显示代理失败并可重试，TDLib 状态不受污染。
- [ ] 不出现「代理崩溃导致必须重新登录」的现象。

### 7.12 与 TDLib / 媒体策略的兼容

#### REQ-PROXY-110 自有 VPN 不被判定为漫游

**EARS**：当 HmChat 自建 VPN 生效时，系统的网络类型判定不应把当前网络判为蜂窝或漫游。

**验收标准**
- **Given** 底层为 Wi-Fi 且代理开启，**Then** 媒体策略仍按「非计费网络」处理，自动下载行为与关闭代理时一致。
- **Given** 底层为蜂窝且代理开启，**Then** 按真实蜂窝策略处理，不额外叠加「漫游」惩罚。
- **Given** 网络类型不可判定，**Then** 保持保守策略并显示可理解提示，不静默关闭下载。
- [ ] 不使用 VPN 标志本身直接推导漫游。

#### REQ-PROXY-111 告知 TDLib 真实网络类型

**EARS**：系统应向 TDLib 传递与真实底层网络一致的网络类型，而不是代理网络的类型。

**验收标准**
- **Given** 代理开启、底层为 Wi-Fi，**Then** TDLib 收到的网络类型与关闭代理时相同。
- **Given** 底层网络变化，**Then** TDLib 及时收到更新，不长期停留在错误类型。
- [ ] 代理开关本身不触发 TDLib 网络类型抖动。

#### REQ-PROXY-112 生效时机与重连提示

**EARS**：当代理在 TDLib 已建立连接后开启时，系统应按验证结果决定是否提示或主动重连，不得静默假设已生效。

**验收标准**
- **Given** 已连接的 TDLib 在新 VPN 建立后仍走旧路径，**Then** 系统提示「网络已切换，建议重新连接」或主动执行安全重连。
- **Given** 重连执行，**Then** 不清空草稿、不重新登录、不丢失当前会话。
- [ ] 该行为基于真机验证结论，未验证前不宣称「自动无缝切换」。
- 【待确认】VPN 对已建立 TDLib socket 的生效时机。

#### REQ-PROXY-113 现有功能回归清单

**EARS**：代理集成后，系统应保持登录、消息、媒体、草稿、搜索等既有能力与集成前一致。

**验收标准**
- **Given** 代理关闭、开启、切换节点三种状态，**Then** 分别为：接收与发送文本消息、加载图片/视频、附件上传下载、草稿保存与恢复、会话搜索可用。
- **Given** 任一回归项失败，**Then** 记为阻断问题，不以「代理本身可用」为由放行。
- [ ] 回归记录覆盖真实服务端行为，不以 mock 代替。

#### REQ-PROXY-114 账户切换不重启 VPN

**EARS**：当用户切换 Telegram 账户时，系统不应重启 VPN 或重新加载内核。

**验收标准**
- **Given** 代理已连接，**When** 用户切换账户，**Then** VPN 连接保持，仅 TDLib 会话按既有逻辑切换。
- **Given** 切换账户导致 TDLib 短暂断连，**Then** 代理状态仍为 `connected`，不显示失败。
- [ ] 账户切换不重复请求 VPN 授权。

#### REQ-PROXY-115 本地回环视频流不受影响

**EARS**：当代理开启时，应用内本地回环视频播放应继续可用。

**验收标准**
- **Given** 代理开启，**When** 播放已下载或本地流式视频，**Then** 播放正常、可拖动进度。
- **Given** 回环地址被路由进 TUN，**Then** 视为缺陷并修复（路由排除或显式绕行）。
- [ ] 该验证在代理开启状态下执行，不在关闭状态代替。

#### REQ-PROXY-116 媒体自动下载策略不回退

**EARS**：当代理开启时，系统不应因此降低媒体自动下载策略或改变用户既有设置。

**验收标准**
- **Given** 用户已开启 Wi-Fi 自动下载，**When** 启用代理（底层 Wi-Fi），**Then** 自动下载仍生效。
- **Given** 用户既有设置，**Then** 代理启停不修改存储与下载设置中的任何开关值。
- [ ] 「代理开启后图片不再自动下载」视为回归缺陷。

### 7.13 构建、许可证与发布

#### REQ-PROXY-117 真实 SDK 26 编译

**EARS**：系统应在真实 HarmonyOS SDK 26 工具链下完成 ArkTS 与 Native 编译，不以 TypeScript 检查替代。

**验收标准**
- **Given** 完整源码与依赖，**Then** `assembleHap` 成功产出 HAP，编译日志无 ArkTS 类型错误与 Native 链接错误。
- **Given** 编译环境，**Then** SDK 版本、nativeCompiler、ABI 与基线一致（`26.0.0`、`BiSheng`、`arm64-v8a`）。
- [ ] 记录编译日期、SDK 版本与产物路径作为证据。

#### REQ-PROXY-118 原生库打包与门禁同步

**EARS**：当新增内核与桥库时，系统应把它们纳入 HAP 打包，并同步更新产物门禁的白名单与测试夹具。

**验收标准**
- **Given** 构建产物，**Then** HAP 的 `libs/arm64-v8a/` 同时包含桥库与内核库，且 SONAME 与依赖关系可解析。
- **Given** 运行 `scripts/ci/verify-hap.py`，**Then** 因白名单已同步而通过，不出现「未登记库」失败。
- **Given** 运行宿主机门禁测试，**Then** `tests/ci-package.test.mjs` 的库列表与许可清单已同步且通过。
- [ ] 无指向构建机绝对路径的 RUNPATH 残留。

#### REQ-PROXY-119 许可文件与第三方通知

**EARS**：系统应在 HAP 内提供内核及其依赖的许可全文，并在第三方通知中登记来源。

**验收标准**
- **Given** 发布构建，**Then** `rawfile/licenses/` 含 mihomo、Go runtime 及各依赖的许可文本，以及项目 GPL 与第三方通知。
- **Given** `THIRD_PARTY_NOTICES.md`，**Then** 新增内核条目（版本、来源、修改说明、对应源码位置）。
- **Given** `docs/LICENSING.md`，**Then** 「实际构建的来源记录」包含固定提交、Go 版本、构建参数与产物哈希。
- [ ] 门禁 `LICENSES` 清单同步更新，缺失即失败。

#### REQ-PROXY-120 GPL 对应源码门禁

**EARS**：在含内核的 HAP 发布前，系统/流程应确认可提供完整对应源码与构建脚本。

**验收标准**
- **Given** 内核二进制随包分发，**Then** 存在可从源码重建同 ABI 产物的脚本与固定提交记录。
- **Given** 源码未补齐，**Then** 发布流程阻断，不得产出对外分发的含内核 HAP。
- **Given** 仅本机调试包，**Then** 明确标注不可分发，且不进入公开 release。
- [ ] `sing-tun` 等本地修改提供 diff 说明。

#### REQ-PROXY-121 不修改签名与 bundleName

**EARS**：系统应沿用用户现有签名配置与默认 `bundleName xyz.3333189.harlgram`，不修改签名材料。

**验收标准**
- **Given** 构建配置，**Then** 未新增、修改或输出签名配置内容。
- **Given** `AppScope/app.json5`，**Then** `bundleName` 保持既定值；如需调整由用户自行配置。
- [ ] 不复制上游工程的签名段或证书文件。

#### REQ-PROXY-122 不引入 Flutter 依赖

**EARS**：系统应保持纯 ArkTS / ArkUI 实现，不引入 Flutter 运行时、插件 HAR 或 Flutter 资源。

**验收标准**
- **Given** 依赖清单，**Then** 仅包含 HmChat 自有本地包与代理桥包，无 `@ohos/flutter_ohos` 及插件 HAR。
- **Given** 产物，**Then** 无 `libflutter.so`、`libapp.so`、`flutter_assets/`。
- [ ] 不复制上游构建残留（`.cxx/`、`build/`、`oh_modules/`、`local.properties`、崩溃 dmp）。

#### REQ-PROXY-123 ABI 范围明确

**EARS**：系统本轮应只提供 `arm64-v8a` 的内核与桥产物。

**验收标准**
- **Given** 构建，**Then** `abiFilters` 仍为 `arm64-v8a`，不混入不匹配 ABI 的 `.so`。
- **Given** 模拟器为其他 ABI，**Then** 明确记录「不支持」而不是安装后崩溃。
- [ ] 文档说明后续扩展 ABI 需要重新构建内核。

#### REQ-PROXY-124 构建可复现与指纹记录

**EARS**：系统应记录内核与桥产物的版本、构建参数与 SHA-256，支持重建核查。

**验收标准**
- **Given** 产物，**Then** 记录大小、SHA-256、Go 版本、构建标签、SDK 版本与编译命令摘要。
- **Given** 重新构建，**Then** 可对照记录判断是否为同一输入。
- [ ] 记录不包含签名、密钥与本机绝对路径。

#### REQ-PROXY-125 体积与安装体验评估

**EARS**：当新增内核与规则资源后，系统应评估 HAP 体积与安装/启动影响，并给出结论。

**验收标准**
- **Given** 发布候选包，**Then** 记录 HAP 大小、安装耗时、首次启动耗时，与基线对比。
- **Given** 体积显著增大（如 >100 MB），**Then** 在文档与商店描述中说明，并评估是否调整资源分发策略。
- [ ] 不在未评估的情况下宣称「体积无影响」。

#### REQ-PROXY-126 商店资质与隐私说明

**EARS**：系统/流程应在发布前核对 VPN 类应用的资质要求与隐私说明一致性。

**验收标准**
- **Given** 发布材料，**Then** 隐私说明覆盖代理配置的本地处理、日志保留与是否上传。
- **Given** AppGallery 要求，**Then** 记录具体资质项与结论；未确认前不宣称可上架。
- [ ] 文案不暗示官方 VPN 或运营商背书。

### 7.14 回归与验收纪律

#### REQ-PROXY-127 现有宿主机测试保持通过

**EARS**：当新增代理领域逻辑后，系统应保持既有宿主机测试全部通过，并为新增纯逻辑补充测试。

**验收标准**
- **Given** 运行 `scripts/test-domain.sh`，**Then** 既有测试零失败，新增代理逻辑测试通过。
- **Given** 新增纯逻辑（状态机、URL 校验、配置解析结果映射），**Then** 位于可测 `.ts` 并纳入测试白名单。
- [ ] 以测试数量与失败数为证据记录。

#### REQ-PROXY-128 未启用代理时行为不回归

**EARS**：当用户从未启用代理时，系统行为应与集成前完全一致。

**验收标准**
- **Given** 全新安装且未导入配置，**Then** 主进程不加载内核、无 VPN 授权弹窗、无额外后台任务。
- **Given** 正常聊天流程，**Then** 启动时间、内存占用、网络行为与基线一致（记录实测值）。
- [ ] 设置页仅多一个入口行，不影响其他入口。

#### REQ-PROXY-129 设备验收记录分列

**EARS**：系统应分别记录设计检查、SDK 编译、设备启动、真实服务端四类证据，互不替代。

**验收标准**
- **Given** 任一需求标记通过，**Then** 有对应的证据类型与日期。
- **Given** 仅在模拟器通过，**Then** 标注「模拟器验证，真机未验证」，不推断真机通过。
- [ ] 截图、stub、mock 不作为真实服务端证据。

#### REQ-PROXY-130 手机单栏优先

**EARS**：本轮应以手机单栏、未展开形态完成功能与 UI 验收。

**验收标准**
- **Given** 指定的手机设备，**Then** 完成代理页全部交互验收。
- **Given** 折叠/展开、平板、多窗口，**Then** 如实标注未验证，不宣称已适配。
- [ ] 不因规范中的未来矩阵而擅自扩大本轮范围。

#### REQ-PROXY-131 文档与接力同步

**EARS**：当行为变更时，系统/流程应同步更新接力与合规文档。

**验收标准**
- **Given** 代理功能合入，**Then** `docs/STATUS.md` 记录修改、命令、结果、未验证项与下一步。
- **Given** UI 变更，**Then** 更新响应式验收记录与 UI 规范中的页面清单（如需）。
- **Given** 许可与依赖变更，**Then** 更新 `THIRD_PARTY_NOTICES.md`、`docs/LICENSING.md` 与 README 功能状态。
- [ ] 只把实际通过的步骤写为通过。

#### REQ-PROXY-132 测试安装隔离纪律

**EARS**：系统/流程不得在持有真实用户会话的设备上执行同 bundle 的测试安装/卸载循环。

**验收标准**
- **Given** 需要设备测试，**Then** 使用 normal signed HAP 覆盖安装或隔离实例。
- **Given** 测试过程，**Then** 不清数据库、不导出密钥、不复用旧库目录。
- [ ] 违反该纪律的验证结果不计入通过证据。

## 8. 需求层数据模型

本节只定义**需求层**需要存在的信息与语义，不定义内核 Action JSON、不定义 RPC 报文字段、不定义文件格式细节。任何与内核交互的具体字段名、参数结构、返回结构均属 §9 待确认范围。

### 8.1 代理配置（ProxyProfile）

| 字段 | 类型 | 需求层语义 | 是否敏感 |
| --- | --- | --- | --- |
| `id` | 字符串 | 应用本地生成的稳定标识 | 否 |
| `displayName` | 字符串 | 用户可见名称，长度受限 | 否 |
| `sourceKind` | 枚举 `subscription` / `localYaml` | 来源类型，用于列表标识 | 否 |
| `sourceRef` | 字符串 | 指向受保护存储中订阅 URL 的引用（非 URL 本身） | 是（间接） |
| `configRef` | 字符串 | 指向受保护配置文件的引用 | 是（间接） |
| `nodeCount` | 整数 | 最近一次成功解析的可用节点数 | 否 |
| `groupCount` | 整数 | 最近一次成功解析的分组数 | 否 |
| `contentHash` | 字符串 | 内容摘要，用于判断订阅是否实际变化 | 否 |
| `updatedAt` | 时间 | 最近一次成功导入/更新时间 | 否 |
| `lastAttemptAt` | 时间 | 最近一次尝试导入/更新时间 | 否 |
| `lastErrorCode` | 枚举 | 最近一次失败分类（见 8.4） | 否 |
| `isActive` | 布尔 | 是否为当前生效配置；全局唯一为真 | 否 |

约束：`sourceRef` / `configRef` 只保存引用，真实内容存放于 Asset 或受保护文件（REQ-PROXY-083）。列表展示只使用非敏感字段（REQ-PROXY-034、093）。

### 8.2 节点（ProxyNode）

| 字段 | 类型 | 需求层语义 | 是否敏感 |
| --- | --- | --- | --- |
| `id` | 字符串 | 组内稳定标识 | 否 |
| `displayName` | 字符串 | 展示名 | 否 |
| `groupId` / `groupName` | 字符串 | 所属分组 | 否 |
| `protocolLabel` | 字符串 | 协议类型展示（如 SS / VMess 等文字标签） | 否 |
| `latencyState` | 枚举 `unknown` / `testing` / `ok` / `timeout` / `error` | 测速状态 | 否 |
| `latencyMs` | 整数或空 | 已测得的毫秒值；仅参考 | 否 |
| `availability` | 枚举 `available` / `unavailable` | 当前配置下是否可选 | 否 |
| `unavailableReason` | 字符串 | 不可用原因（用户可读，脱敏） | 否 |
| `isAutoGroup` | 布尔 | 分组是否为自动选择类型 | 否 |

约束：模型中**不存在**密码、UUID、私钥、服务器地址等字段；这些内容只存在于受保护配置文件中，UI 不持有（REQ-PROXY-050）。

### 8.3 代理设置（ProxySettings）

| 字段 | 类型 | 需求层语义 |
| --- | --- | --- |
| `scope` | 枚举 `global` / `harlgramOnly` | 代理范围，默认 `global` |
| `enabledIntent` | 布尔 | 用户希望代理处于开启状态（意图，不是运行事实） |
| `lastActiveProfileId` | 字符串或空 | 上次生效配置，用于重建 |
| `lastSelectedNodeId` | 字符串或空 | 上次选中节点，用于恢复 |

约束：`enabledIntent` 不得用于推导运行状态；运行状态只来自 §8.4（REQ-PROXY-011、065）。

### 8.4 运行时快照（ProxyRuntimeSnapshot，非持久真值）

| 字段 | 类型 | 需求层语义 |
| --- | --- | --- |
| `state` | 枚举（§6.1 六态） | 唯一运行状态 |
| `coreVersion` | 字符串或空 | 内核版本；不可得为「未知」 |
| `activeProfileId` | 字符串或空 | 内核实际加载的配置 |
| `activeNodeName` | 字符串或空 | 内核实际生效出口节点名 |
| `startedAt` | 时间或空 | 本次连接建立时间 |
| `errorCode` / `userMessage` / `detailRef` | 结构化错误 | 分类、用户文案、可选详情引用 |
| `protectFailureCount` | 整数 | protect 失败计数（诊断用） |
| `sessionId` | 字符串 | 本次会话标识（不持久化、不含 token） |

错误分类（需求层，最小集合）：`core_missing`、`core_init_failed`、`tun_create_failed`、`auth_denied`、`config_invalid`、`config_missing`、`rpc_unavailable`、`rpc_auth_failed`、`protect_degraded`、`timeout`、`unknown`。

### 8.5 不变量

- 同一时刻只有一个 `isActive = true` 的配置（REQ-PROXY-035）。
- 节点选择属于「配置 + 用户」维度，切换配置后不得沿用不存在的节点（REQ-PROXY-048、055）。
- 测速结果不是持久真值，不得写入配置或作为启动依据（REQ-PROXY-059）。
- 任何持久化结构中不得出现明文凭据；`sourceRef` / `configRef` 只是引用（REQ-PROXY-083）。
- 运行时快照在进程重建后必须重新探测，不得从持久化直接恢复为 `connected`（REQ-PROXY-011）。
